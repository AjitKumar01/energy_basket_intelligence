# The synthetic stress world

`scripts/synthetic/generate_stress_world.py` writes a complete synthetic retailer in the
canonical input format, so the pipeline can be run end to end without any external data. It is
deliberately **not** generated by the Version-4 model: there is no energy function, pair matrix,
category penalty or size potential. Baskets come from a procedural shopping story built from
standard marketing-science mechanisms, so a model that fits it has to earn the fit.

## 1. How baskets are generated

For each household trip (household, store, week):

- **Missions.** A trip has 1 + Poisson(intensity\(_h\)) missions (breakfast, lunch, dinner
  recipe, snacks, cleaning, baby, party, top-up), drawn from the household's mission
  preferences. Each mission is a sparse list of needed categories; recipes add all-or-none
  category triplets, so complementarity is higher order and mission-driven.
- **Nested choice.** Each needed category picks a subcategory, then a product, by nested logit
  (nest parameter 0.5). Substitution comes from "one product per need", nested, never uniform.
- **Catalogue.** Zipf quality inside categories and uneven subcategory sizes (a long tail).
- **Heterogeneity and dynamics.** Household taste over three product attributes drifts weekly
  (AR(1)); loyalty to the last product bought in a category; pantry inventory, where a
  promotion purchase suppresses that need for a few weeks (stockpiling); occasional variety
  seeking (two products for one need); impulse additions.
- **Prices.** Chain-level weekly prices with noise and promotions (25% off with a display).
  Reference-price response with loss aversion (a rise hurts twice as much as an equal cut
  helps), and household-specific price sensitivity.
- **Observation.** Heavy-tailed visit rates, store launches seen through a retail feed, and
  unrecorded stockouts (3% of cells).

Defaults: 3,000 households, 15 stores, 6 departments × 8 categories (about 476 modeled
products), 52 weeks split 32 / 10 / 10 into train / validation / test, mean basket about 9
items. `--categories-per-department` and `--mission-variants` scale the catalogue (give each
mission `--mission-variants` category templates, roughly one per 48 categories, so larger
catalogues are still bought).

## 2. Causal price truth

Every trip has its own random stream. For `--scenario-products` products (default 16) bought
at least 30 times in training, the test weeks are re-simulated from the same starting state
with that product's price × 0.8 and × 1.2, using common random numbers. The resulting changes
(the product's own purchase rate, its same-subcategory siblings, the rest of its category, and
basket size) are the true causal effects of those price changes, written before any model is
fitted.

## 3. Outputs

Under `--output <dir>`:

| File | Content |
|---|---|
| `canonical/` | the canonical directory (`transactions`, `products`, `store_week_prices`, `promotions`, `shopping_opportunities`, `build_audit.json`) |
| `observed.npz` | the same observed data as arrays |
| `truth.json` | world summary (products, households, trips, basket sizes, run time) |
| `counterfactual_truth.json` | the declared price scenarios and their true effects |

The shipped configuration `configs/datasets/stress_world_category.json` expects
`--output data/stress_world` and builds the model-data bundle with the merchandise-category
partition, the `retail_first_sale` availability rule and the `advertised` promotion feature.

## 4. What the world is for

It exercises every pipeline stage on data the model did not generate: likelihood, generation
and certification run as they would on real data, and `counterfactual_truth.json` lets a
model's price counterfactuals be compared with the true effects. It has two known features the
Version-4 model cannot represent exactly: substitution between siblings of a subcategory
(the partition is per category, and \(\Phi\) expresses only complements) and loss-averse,
asymmetric price response (the model is symmetric in log price). See
`JOINT_REFINEMENT_STAGE.md` §3 and §5 for the measured consequences.
