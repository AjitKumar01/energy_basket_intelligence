# Synthetic verification of probability foundations and price responses

This branch implements the corrections in
[`PROBABILITY_FOUNDATIONS_AND_PRICE_COUNTERFACTUALS.md`](PROBABILITY_FOUNDATIONS_AND_PRICE_COUNTERFACTUALS.md).
It retains the current common/relative price specification. Setting its multiplier to
one is an oracle-audit ablation, not a change to the production model.

## Implemented changes

- The additive elasticity penalty differentiates exact DP size expectations along the
  actual heterogeneous-price direction. Fourth-order symmetric differences are
  differentiable through the native first adjoints; a step-size envelope and
  second/fourth-order agreement check expose numerical fidelity. The old catalogue-mean
  coefficient proxy is no longer used by the production trainer.
- A shared price-context transformation updates both item prices and their offered-set
  mean. The price/generation audit and segment pricing environment use it.
- A stable single-utility tilt computes new incidences and the partition ratio from
  factual first/pair moments. It explicitly does not treat a split-price action as a
  single-utility action.
- The stratified fit has eight draws in each of its three largest-size bands. Both the
  absolute ESS floor of 2 and fractional floor of 0.20 apply to cross-fit and final fits.
- Likelihood and interaction cross-fit uncertainty uses household clusters. The legacy
  adjacent-rule error-bound field is retained for compatibility, with explicit metadata
  identifying it as an empirical allowance, not a mathematical integration bound.
- Additive checkpoint metadata distinguishes validation early stopping from stationary
  optimization. Resuming an old proxy-elasticity optimizer under the new penalty is
  rejected; a fresh corrected-objective run is required.

The price penalty adds four perturbed exact DP evaluations to an update when enabled.
It therefore increases training cost. It changes the calibration target, not the energy
formula. Previously fitted real-data checkpoints and their empirical results have not
been regenerated by these synthetic runs.

## Running and monitoring

From the repository root:

```bash
python -m pytest -q
python -u scripts/run_synthetic_experiment.py --profile smoke --threads 4
python -u scripts/run_synthetic_experiment.py --profile full --threads 4
```

Each invocation creates a new timestamped `artifacts/synthetic_probability_*` directory.
To specify its location, pass `--output-dir artifacts/<new-run-name>`. An existing run
directory is rejected to avoid overwriting evidence. To run independently of a terminal,
use an available session manager, for example:

```bash
screen -dmS probability_synthetic_full python -u scripts/run_synthetic_experiment.py \
  --profile full --threads 4 --output-dir artifacts/synthetic_probability_full_20260913
```

Every run contains:

| File | Purpose |
|---|---|
| `pipeline.log` | Combined persistent output from every stage |
| `manifest.json` | Current stage, run status, PID, commands, timings, branch, Python version, source hashes, and report hashes |
| `native_build.log` | Native exact-DP build |
| `probability_foundations.log` | Production-code oracle checks and randomized-price experiments |
| `probability_foundations.json` | Numerical errors, fixed tolerances, sampling budgets, fit results, and pass/fail gates |
| `exact_interaction_recovery.log` | Existing exact-support null/weak/strong interaction benchmark |
| `synthetic_exact_certification.json` | Interaction recovery results |
| `complete_retailer.log` | Well-specified retailer fitting and evaluation |
| `synthetic_retailer_experiment.json` | Purchase, basket, quantity, counterfactual, and policy results |
| `misspecified_retailer.log` | Deliberately misspecified retailer fitting and evaluation |
| `synthetic_retailer_misspecified.json` | Robustness results under misspecification |

For the explicitly named full run above:

```bash
tail -f artifacts/synthetic_probability_full_20260913/pipeline.log
```

The manifest changes from `running` to `completed` or `failed`. A stage failure exits
nonzero and identifies the failing command. Source hashes are checked before and after
each stage: changing source or test files during a run invalidates it. The full run
should be allowed to finish before modifying those files.

`completed` means all commands finished and the foundation audit passed its declared
gates. It does not mean every recovery experiment supports an efficacy claim. The
well-specified and misspecified recovery reports must still be interpreted; their
statistical results are not silently turned into guaranteed improvements.

## Oracle coverage

The full foundation stage runs three fixed seeds. Each includes:

1. Actual `RaggedModel.energy` against an independently assembled dense off-diagonal
   energy on every supported basket in a 10-product, size-1-through-5 retailer (637
   baskets), for zero/nonzero interactions and price multipliers 1 and 2.4.
2. Native additive log normalizers and complete size distributions against enumeration.
3. All-product price Jacobians against symmetric price perturbations of the actual
   utility/context map, finite bundle-price reweighting, and finite single-utility tilts.
4. Corrected elasticity values and parameter gradients of its penalty against exact
   covariance derivatives for utilities, product/household price factors, category
   coefficients, and the size potential.
5. Interacting H–S/Smolyak log normalizers and their scores against enumeration.
6. Twelve thousand exact additive reverse draws per context, with simultaneous
   Hoeffding moment checks. For interacting baskets, 48 independent SMC runs with 256
   particles each provide moment and normalizer-ratio checks. SMC runs, rather than
   dependent individual particles, are the uncertainty units.
7. A randomized-price world with 1,200 heterogeneous households, 180 opportunities each,
   explicit no-purchases, and known basket responses. Horvitz–Thompson action contrasts
   use the known assignment probability; household-clustered intervals are compared
   against oracle effects on purchase, one item's incidence, size, and a distinct-item
   revenue proxy.
8. Three native-DP fits from the same initialization and sampled training/validation
   baskets: likelihood only, legacy elasticity proxy, and corrected elasticity response.
   A known oracle elasticity is supplied to the two penalized fits solely to isolate
   their calibration behavior. It is explicitly not an estimated real-data target.
   Validation likelihood selects the checkpoint; oracle KL and response/parameter errors
   evaluate recovery. The corrected fit must improve over its starting oracle KL; its
   comparison with the legacy fit is reported without requiring a favorable outcome.
9. Adversarial concentrated weights in bands with 3, 4, 5, and 8 draws. The new gate must
   reject each, including cases that satisfy the old fractional criterion automatically.

Numerical identity tolerances are fixed before the run: `2e-7` for the direct/DP/price
identities and penalty gradients, and `2e-5` for the finite Smolyak value/score audit.
The sampling report records its separate statistical tolerances and finite-SMC bias
allowance. These are finite verification criteria, not universal convergence proofs.

The later existing interaction benchmark includes null, weak, and strong interactions.
The complete retailer experiments enumerate all 60,459 nonempty baskets of sizes 1–6
from 20 products and include arrival, store choice, quantities, costs, randomized
promotions, and a budgeted decision experiment. They supplement the foundation audit;
they do not replace the direct tests of the production model and its numerical kernels.

## Interpretation boundaries

Exact enumeration is an independent numerical oracle for the finite synthetic worlds.
Sampling tests and fitting experiments remain random, and mathematical proof remains
the role of the derivations. Synthetic randomized actions establish known experimental
truth by construction; they do not identify causal price effects in observational
dunnhumby data. The real-data model still conditions on a nonempty modeled purchase and
does not acquire an arrival, quantity, or causal identification model from these tests.
